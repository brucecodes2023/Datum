\subsection{How the work was run}
\begin{itemize}
  \item \textbf{Test instances only.} Every test ran in a throwaway FreeCAD profile (\code{FREECAD\_USER\_HOME}, a
        copy of the settings), at most three FreeCADs at once through \file{agents/fcslot.sh} (your open Keystone
        counts as one), each run narrated in \file{agents/testlog.txt}. The vault Vector was only read; every
        write went to a copy.
  \item \textbf{Agents in one checkout.} A separate worktree would have meant a full rebuild (ccache has no
        base\_dir), so all agents shared the repository. Builds and C++ edits go through a lock
        (\file{agents/lock.sh}: \code{build}, \code{take}, \code{drop}) so no build sees half-written C++.
  \item \textbf{Commits by path.} Two agents staging at the same moment once put one agent's files in the other's
        commit (\code{670cda6} carries the ASM-06 GUI files under a MOD-05 message; history was not rewritten,
        \code{6dd13ff} records it). Since then every commit names its files (\code{git commit -- <paths>}), and
        shared files such as \file{Init.py} are committed from a temporary index holding only the agent's lines.
  \item \textbf{Screens.} One early test grabbed a screen area and caught another window; an Assembly appeared in
        that test's document. Since then screenshots are rendered off screen only and no test raises a window.
  \item \textbf{Keystone.} Each new build is staged in the scratchpad under the build lock, and a watcher swaps it
        into \file{/Applications} and reopens it when you quit Keystone; the previous copy is kept in the
        scratchpad.
  \item \textbf{Installs.} networkx~3.5 was added to \file{pixi.toml} and the project's pixi environment for
        SheetMetal (\eref{MOD-06}); it is bundled in Keystone.
\end{itemize}

\subsection{Bug round, 26 October}

A dedicated session ran the whole BruceWorx GUI suite after the 25 October commits (37 modules plus the
Assembly joint and BOM tests: 611 tests), chased every failure to its cause, closed the self-contained gaps
above, and ran an exploratory smoke on a copy of the Vector vault.

\paragraph{Baseline.} 4 problems in 611 tests, all order-dependent (every module passed on its own):
TestBruceWorxStudio failed twice after TestBruceWorxHardware; TestBruceWorxGaps and TestBWJoints failed only
in the GUI run; the Report view held fifteen ``Cannot access attribute 'Objects' of deleted object'' from the
configuration observer. A probe that created a part after every module showed the studio shading's timer still
``active'' but never firing after the Hardware GUI command tests: its \code{timeout} had no receivers left.

\paragraph{PySide drops every function connection (the big one).} In PySide 6.8.3, a plain Python object (not a
QObject) that connects two or more widget signals to its own bound methods takes, when it is garbage collected,
\emph{every} connection in the application whose receiver is a plain function or lambda with it: menu actions,
timers, the studio's observer timer, the bridge's server. Reproduced in isolation: two bound-method connections
and a \code{del} are enough; one connection, a QObject subclass, a lambda or a \code{functools.partial} as the
receiver are fine. Hole Preset's dialog helper was the first to die in the suite; in Keystone one Hole Preset would
have left the studio shading, the bridge and the menu lambdas dead for the session. Fix:
\file{bruceworx\_slots.py} --- \code{slot(self.method)} returns a closure PySide keeps (same lifetime as before:
the object lives while a sender does), applied at 57 sites in eleven modules; the hardware dialogs are now
deleted once answered; \code{TestBruceWorx} lints the folder for the pattern and \code{TestBruceWorxHardware}
checks a dialog's teardown leaves a reference connection alone.

\paragraph{FreeCADCmd crashed at exit (the two crash reports of 25 October, 18:30 and 18:51).} Making or changing a
section plane headless queued \code{QTimer.singleShot} for the view refresh; FreeCADCmd never runs it, and the
functor was released after Python had finalised (SIGSEGV in \code{PyGILState\_Ensure} from Shiboken). Found by
spying on \code{singleShot} while the interference tests ran headless: one call, from
\code{bruceworx\_section.schedule()}. It now returns when the GUI is not up; the headless run exits 0 and a test
keeps it so.

\paragraph{Smaller fixes.} The configuration observer's queued calls look their document up by name (closed
meanwhile: nothing to do). \code{JointObject.undoPreSolve} survives a joint without a view provider (TestBWJoints
in the GUI). The Gaps test tolerates a sub-window on its way out and a module before it leaving no active
sub-window (scaffolding, not behaviour).

\paragraph{Right panel (your screenshot).} (1) Two ``Sel\ldots ent'' tabs: your profile has the Report view in the
right panel, and the strip gave every dock that is not ours the open command's word. Only the Tasks dock does now
(by its title, which the task card sets); another dock keeps its own name, open command or not. (2) The dialog's
OK/Cancel not visible: not reproduced with a fresh profile, with your widget list (Report view) and window height
1191, nor with the suite's profile, Start page active each time --- the buttons sat inside the panel and the
window. A GUI test now holds that. If it still happens for you, a screenshot with the window size, or a live look
at \code{TaskEditControl}'s geometry, is the next step. (Someone edited \file{OverlayWidgets.cpp} and the strip's
layout in the tree during the afternoon; that work is theirs and is not in these commits.)

\paragraph{Gaps closed.} \emph{Configurations:} a link's Browser row reads ``BW-1001-S $\cdot$ Short'' (also while
it follows its part's active row); a cell the Configuration Table drives shows ``per configuration'' in the
Parameters tab with the row value beside it and a tip naming the row, and its value stays editable (the edit goes to
the active row). \emph{Interference:} every occurrence carries a signature (part, its own shape's hash, the placed
solids' box and volume) and a measured pair is kept by the two signatures, the gap and the contacts switch (4000
